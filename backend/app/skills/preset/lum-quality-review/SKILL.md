# 用例评审（v2）

> v1 是**模块级**评审：把一屏 `[P1] 标题（N 步）` 塞进一次 prompt，让模型给四个维度打分。
> 出来的结论是「缺少安全测试场景」「部分前置条件不够具体」——放到任何项目都成立，
> 也没法照着改。它还编统计数字（说 50 条没预期结果，库里真实是 5 条）。
> **v2 换成逐条评，并且把判定权收回代码。** 实现见
> `app/services/review/{evidence,reviewer}.py`，这份文件只记口径。

## 评审对象：一条用例的全部产物

步骤原文 + 接口场景每一步的 URL/headers/断言/提取物 + UI 脚本正文 +
最近几次执行记录 + 同模块邻居标题。缺了断言和脚本，评审只能对着标题说套话。

## 两段式：平台先出事实，模型只判判断题

| 谁判 | 判什么 |
|---|---|
| **平台代码** | 恒真断言、not_exists 缺基准、写完没读回、只打控制面、对照组塞一条、只断状态码、UI 脚本硬伤（sync_playwright / 写死地址 / 文案硬编码 / 清 storage 换角色）、按承诺还欠哪几维 |
| **模型** | 场景本身合不合理、该验的验没验、漏了什么、预期是不是照实现抄的、UI 脚本验的是不是该验的东西 |

模型**不许推翻**平台给的事实，也不许自己数数（统计一律由平台算）。
它复述平台那条时，保留平台判的严重程度 —— 实测它会把 blocker 说成 minor。

## 六个维度

| 维度 | 权重 | 看什么 |
|---|---|---|
| 场景合理性 | 20 | 一条只验一件事；对照组没塞一条；标题能看出测什么；类型/目标层级和内容匹配 |
| **验证点到位** | **25** | 有没有真生效证据（跨入口/UI 可见）；写完读回；断言不恒真；断言有内容不只有状态码 |
| 接口必要性 | 10 | 有没有多余调用（重复登录、无断言的读）；能用共享资源却自己造；步骤粒度 |
| UI 脚本正确性 | 15 | 选择器语义化；等待策略；多角色用独立 context；文案走占位；断言是 UI 可见事实 |
| 本条覆盖完整性 | 20 | **只判这一条自己承诺的东西验全了没有**（标题和预期里说到的每件事）。模块级缺口（越权、幂等、边界、异步收敛、删除残留）走 `coverageGaps`，是情报，**不进这一维的分** |
| 可执行与纪律 | 10 | 变量分层、无写死、前置自足、环境卫生、国际化 |

验证点到位最重 —— 这一轮外部 CC 的返工**全部**出在这一维。
不适用的维度自动摊掉权重（没写 UI 脚本就不评 UI 那一维，
给一条只承诺步骤的用例扣 UI 分是在惩罚它没承诺的事）。

## 判定（写在代码里，不问模型）

```
有 blocker            → rejected（哪怕加权 95 分）
major >= 2 处         → rejected
没真跑成功            → inconclusive（无法审核：既不算通过也不算打回）
其余                  → approved
```

**分数不参与判定**，只做排序和体检。每一维的分是模型给的，同一条用例两次评审拿 86 和 78
是常事 —— 拿抖动的数当闸门，①结论不稳定人就不信了，②「78 低于 80 线」没法照着改，
而「这两条必须改」可以。（原来这里写的是「加权 < 80 → rejected」，2026-08-19 改掉了。）

`blocker` 的定义是「放进回归就是**假绿**或者根本跑不了」：断言恒真、只断控制面状态就当
生效、预期照着实现抄（把 bug 固化成预期）、UI 脚本必挂。

为什么判定不给模型：让它自己说 approved，一句"整体不错"就能把 blocker 盖过去。
分数可以商量，闸门不行。

## 入口

- 列表「AI 评审」：勾选了评勾选的，没勾评当前模块（逐条，上限 30 条）
- 用例详情「AI 评审」：单条，还有「先跑一遍再评」（真跑接口场景，debug 模式不进通过率）
- MCP `lum_review_case`：**CC 回推完自己先过一遍**，blocker 不许留着交上去

结论落库到 `review_status` / `quality_score` / `review_reason`（含 findings，
人点开能看到"凭什么不过"）。
