### 1.3 但有一个区分**该留下**：只读绑在「无向」上，不绑在「谁的环境」上

真正让 `SAFE_TO_CLICK = ("read",)`（`qa_survey_guard.py:78`）成立的理由不是"别人的
环境"，是**它不知道那个按钮会干什么**：

- **枚举是无向的**：走到一页，看见一个不认识的控件，要当场决定点不点。
  在**我们自己**的环境上无向乱点，点到「删除团队」一样是灾难。
  所以 `unknown` 不点这条**保留**，理由改写成「无向探索」。
- **UI 脚本是有向的**：我们写的，知道点什么，自带清理，`residue.py` 事后查账。
  这里不需要守卫，也从来没有过。

**推论：能不能写，看的是「知不知道自己在动什么」，不是「爬虫 vs 脚本」。**

- 别人的数据、系统预置的数据 → **无向**，一个写按钮都不点。这条永远成立。
- 自己亲手造出来、名字带自己前缀的那一条 → **有向**：在它身上点编辑/删除，
  我们知道点的是什么，也知道怎么清。判据见 §12.2。

⚠ 上一版这里写的是「**不给爬虫开写权限，写操作走 UI 脚本**」，
**2026-09-04 作废，正文已删**（免得有人照着它再推一遍）。
理由那半句是对的，结论下窄了：它把"有向"绑在了「这段代码是谁写的」上，
而真正的判据是「这条数据我认不认识」。

## §4 被否掉的省事写法：「倒推他在页面上怎么操作」

用户原话提到「倒推出他在页面怎么操作的」。**这一步不做**，理由：

他的 bash **根本不经过页面** —— `api_get "/agents/${ID}"` 直接打 BFF。
给一个没有 UI 语义的东西编一段 UI 语义，编出来的东西**没有判据能验对错**，
编错了不报错。这正是本平台反复要防的形状（同 `qa_catalog_review` 里
`unmet`/`blind` 禁止模型编的那条）。

**正确方向是反过来：不从脚本推页面，从页面推脚本。**
页面上点了 X、发出 `POST /a/b` → 去 245 个端点里查有没有人打过 `POST /a/b`。
集合比对，纯代码，跟 `services/review/traffic_diff.py` 的 `norm()` 同一套归一化。

顺带一条已确认的好消息 —— **不需要任何跨层映射**：

```sh
# QA 仓 config/env.sh
BFF="${BFF:-http://127.0.0.1:4000}"
API="${API:-${BFF}/api/v1}"          # 脚本打这个
WEB_URL="${WEB_URL:-http://127.0.0.1:3000}"   # 页面
```

`api_get()` 拼的是 `${API}${path}` —— **他打的就是页面在打的那个 BFF**。
（用户确认：QA 仓的要求就是这样，不是这样就是他写错了。）

- **R 边**：现成的 `qa_route_table.py`。

| | 结论 |
|---|---|
| P ∖ Q | 页面上在用、他一条没测 ← **这就是「覆盖全不全」** |

### 10.1 R 边（路由表）此前一条路由都没读进来

`GET /api/docs/routes` 打得通、**200、676 条**，而 `parse_routes` 认出来 **0 条**：
UAG 那头的形状是「组是一层对象、路由挂在组的 `routes` 里」
（`{"prefix":"adapters","count":18,"routes":[…]}`），解析器只认扁平的三种形状。

结果不是报错，是一句**写得工工整整的降级声明**：

> `available=False` ／「本轮无路由表，G2 未验证」

**降级路径诚实，不等于降级本身是对的。** 报告上那一维一直在白跑，
而它长得和「这个环境确实没有路由表」一模一样 —— 不真跑一趟，这件事可以一直不被发现。
（这也正是批 1 存在的理由：§3 那句「选择器全部来自源码阅读」说的是 QA 那边，
而我们自己这边一样有一整维是靠读代码推出来的。）

修在 `qa_route_table.py`：加 `_nested_group` + 递归 `take`，
且**既像一条路由又挂着子路由时两边都收** —— 只收一边就是静默少端点，
而少一个端点 = 少一类缺口，永远不报错。封样在 `tests/test_qa_route_table.py`
的 `Test组是一层对象`（12 → 21 条）。

### 10.2 110 行兜底路由会变成 83 条假 G2（占报告的 37%）

676 行里有 110 行是路由框架的 no-route 兜底：

```json
{"method": "echo_route_not_found", "path": "/api/v1/agents/*", "name": "v4.init.func1"}
```

`method` 那格漏出来的是**处理函数名**，`path` 是通配。这种行原样收进 R 边之后，
每一行都会稳定产出一条 **G2**（P 边不会有 `ECHO_ROUTE_NOT_FOUND /api/v1/*`
这种流量、清单也不会去测它）。实测差值：

| | G2 条数 | 归不到域（`unattributed`） |
|---|---|---|
| 扔掉那 110 行（现在） | **144** | 47 |
| 不扔 | 227 | 68 |
| 差 | **+83（占 227 的 37%）** | +21 |

假缺口的害处不是"多几行噪声"，是**它按住真缺口**：144 条里挑哪个先补是个判断题，
227 条里有 83 条是噪声就不是了。

判据是**形状**不是动词白名单（`_skip_reason`）：方法名非纯字母 → 不是动词；
路径带 `*` → 不是可寻址端点。白名单要年年补，而补漏一个 = 静默少一个真端点。
实测保留了 PROPFIND/REPORT/TRACE/CONNECT 这些冷门但真实的动词。

**扔掉的行分两桶，都得有数**（`qa_route_table` 模块头写了理由）：
`unreadable`（形状不认识 ⇒ 我们的解析器该改）vs `skipped`（认识、但不是端点 ⇒
被测系统就长这样）。合成一个数就分不出下一步该干哪件事；
两格都常驻渲染（页面上「路由表读不到的」／「不算端点扔掉的」）——

## §11 批 2 活体实测（2026-09-04，同一套环境）

### 11.1 「开层按钮」的词表是子串匹配 —— 表头 `Created At` 被当成了「新建」

第一趟量出来：`controlsClicked` 255，`dialogsOpened` **0**。
255 次点击里 234 次是**跳转**（`dialogsNavigated`），一层都没开出来。

原因是 ASCII 词按**子串**匹配：表头 `Created At` 含 `create`、
`Address` 含 `add`、`Preset` 含 `reset`。于是每页三个点击名额，
全被左侧导航和表格表头吃光，真正的「新建」按钮**一个都没轮到**。

改成 ASCII 走**词边界**、中文继续走子串（汉字在正则里也是词字符，
`\b新建\b` 在「新建团队」里两边都不是边界 —— 中文一走词边界，整张中文词表
一条都不命中）。封样在 `tests/test_qa_survey_guard.py::TestL2词表按词边界匹配`。

### 11.2 链接和表头**不该占开层预算**

词表修好之后仍然是 `dialogsOpened 0`。因为预算（每页 3 次）是**先到先得**，
而链接、标签页、表头在 DOM 里排在按钮前面。它们点下去是**换页/排序**，
不是开层 —— 照旧采集、照旧算「页面上有这个控件」，只是**不占开层名额**。
判据走 `NON_OPENER_ROLES`（`a`/`link`/`tab`/`menuitem`/`treeitem`/`columnheader`…）
加「带 `href` 的一律不算」，**没有一个词是产品名词**。

### 11.3 这个产品的「新建」大多**跳一页**，不是弹一层 —— 跳走的那页此前被丢掉

22 次开层点击里 **11 次是跳转、弹层 0 次**。原先跳走了就 `goto` 回来，
**把落地地址扔了**。而表单就在那一页上 —— 于是「点了 22 下」在账本上
一切正常，表单字段却一个都枚举不到。

改成：跳到的地址进**同一条**菜单发现队列（两者都是「页面自己说它还能去哪儿」，
分两套只会让预算算两遍），跟菜单读到的页同等待遇。

### 11.4 表格每行同一个 `data-testid` → 整趟 200+ 页一格都落不下来

第二趟跑完落库时炸了：`duplicate key … uq_qa_page_survey_items_key`，
撞的是 `/monitoring/request-logs::expand-row-button`。
成因不是 bug，是**常见写法**：产品在表格每一行上放了同一个 `data-testid`，
一页于是出现 6 个一模一样的 key。

**探测器该留，但不该把病人打死。** 一条撞库让 214 页 × 7 角色的产物
全部落不下来，报出来是 `status=failed` —— 那和「这一趟根本没跑」
在页面上长得一模一样。改成在**采集处**合成一行（那里看得见它们是同一页上
并排的兄弟节点），并把撞了几次记成明账 `anchorCollisions` / `anchorCollisionKeys`。
落库路径一个字没改，跨分片仍然**不许**合（那一层分不清「撞了」和
「两个角色都看得见」）。这个数**0 也渲染** —— 缺键在页面上显示成「没算过」，
等于把刚挪过来的探测器悄悄拆了。



### 11.5 「弹层」的判据是照 antd 写的 —— 换个 UI 库整维恒 0，报告上一点痕迹都没有

前面三条修完，`dialogsOpened` **还是 0**。到这一步已经不能再猜了：
「层没开」和「层开了但我们认不出来」在账本上是同一个 0。

于是单独写了一个只读探针：用 `admin` 登进去，点 `/adapters` 的「新建」，
把点前点后的 DOM 快照做差集。**层是开了的** ——

```
＋ div|role=|cls=fixed inset-0 z-50 bg-black/80        ← 遮罩
＋ div|role=|cls=relative flex h-full w-full sm:w-[480px] … bg-background shadow-lg   ← 面板
＋ button|role=combobox / div|role=radiogroup / button|role=radio                     ← 层里的控件
```

面板上**既没有 `role="dialog"`，也不是 `.ant-modal-content`**。
而我们的判据当时就是那一串：`[role=dialog], [role=alertdialog],
.ant-modal-content, .ant-drawer-content` —— 照 antd 写的。
换一个 UI 库（这里是 Radix/shadcn 那一路），**整个弹层维度静默归零**，
而报告上它和「这个产品没有弹窗」长得一模一样。

顺带查清了另一半：主爬用的是只读账号 `auditor`，它看到的「新建」是
**灰的**（`disabled`）—— 那是产品的正确行为，本来就已经进了 G5。
所以两个原因叠在一起，把一个"判据写死了"的 bug 藏得严严实实。

**改法是把判据从「它叫什么名字」换成「它表现得像不像一个层」**，两条路：

- **标准路**：`role=dialog` / `role=alertdialog` / `aria-modal=true` —— 有就直接算。
- **兜底路**：点完之后**新冒出来的**、`position` 是 fixed/absolute、
  `z-index ≥ 20`、面积 ≥ 240×160 的可见块；同一时刻有好几个就挑
  **装着表单控件最多**的那个（遮罩层控件数是 0，面板才是要枚举的东西）。

「新冒出来的」是这条兜底路能不能用的关键：点之前先给现有的候选盖一个
`data-qa-pre`，点完只看**没盖章的**。不这么做的话，页面常驻的吸顶栏、
侧边抽屉也满足 fixed + 高 z-index + 够大，随便点一下都会「开出一个层」，
整页控件挂到那个按钮名下 —— **不是少一条账，是一条错的账，而且比真相好看**。

认出来之后就地盖 `data-qa-layer="1"`，后面枚举和关闭都认这个章。
"层的范围"只判定一次，不会枚举时按 A 算、关闭时按 B 算
（关不掉却以为关掉了，后面几次探测就全在同一个层上点）。

两条路**分开记账**（`layersBy: {role, geometry}`，**两格都 0 也渲染**）：
兜底那一格常年为 0 说明产品守 ARIA；它一旦变成大头，就该去问前端为什么
层上没有 `role="dialog"` —— 我们认得出，但别人写脚本会很难定位。
再留 20 条 `layerShapes` 样本（哪一页、哪个按钮、多大、里面几个控件），
否则「判错了」和「真是那样」事后没法回看。

⚠ **别退回写类名。** 类名是某个 UI 库的实现细节，这套东西要能换产品跑。
封样在 `tests/test_qa_survey_click_and_menu.py::Test层怎么认出来的`，
其中一条直接拿判据正文去搜 `ant-` / `MuiDialog` / `chakra` / `el-dialog`。

## §12 需求纠正（2026-09-04 下午，用户当场定）：探索测试 = **真的去操作**，不是把元素记下来

**用户原话**：「你要在知道了这个域涉及到哪些页面后，去对应的页面做探索测试，
自己去点击一下、操作测试下，然后把涉及到的功能和 api 记录下来，再比对脚本和场景
覆盖到没有 —— 不是把所有的页面元素记录下来。**不创建怎么编辑？不创建怎么知道
还有更多的页面解锁呢？**」

### 12.1 前面做的到不了，缺的不是覆盖面而是**状态**

批 1 + 批 2 做完的是：把每一页开一遍、菜单往下走、把弹出来的表单字段列出来。
**它的天花板是「页面此刻长什么样」。** 而绝大多数功能**在空列表上根本不存在**：

- 列表是空的 → 「编辑 / 详情 / 删除 / 停用」这些按钮**一个都不渲染**，
  枚举到的就是"这一页只有一个新建按钮和一个搜索框"；
- 没有一条自己的数据 → 详情页、子标签页（成员 / 配额 / 审计 / 版本…）
  **进都进不去**，那些页面在报告上和"这个域只有 3 页"长得一模一样；
- 没走过一次提交 → **一个写接口都观测不到**。第 5 趟量出来的
  `pageLoadEdges 668` 全是 GET，而报告里那 120 条 G2 大头就是写接口 ——
  「他没测」和「我们没让页面发出来过」在那一格里是同一个数。

**所以这不是"再多点几个按钮"的事，是链条的顺序问题：
先造出一条自己的数据，后面那一层功能才会出现。**

### 12.2 判据怎么改：把「无向」变成「有向」，靠的是**只碰自己造的那一行**

§1.3 立的那条规矩是对的，但结论下窄了（原文：「不给爬虫开写权限，写操作走
UI 脚本」）。真正让无向枚举不许点写按钮的理由是**它不知道自己造了什么、也清理不掉**。
那么反过来 ——

> **自己亲手造出来的那一条数据，我们知道它是什么、知道它的名字、
> 也知道怎么删。在它身上做的任何操作都是有向的。**

于是判据从「写按钮一律不点」改成两条，**都跟域和产品无关**：

1. **新建**：每一页最多走一次「新建」全程（找到表单 → 填 → 提交）。
   造出来的东西名字带**固定前缀 + 随机尾巴**（如 `qa-probe-7f3a`），
   这是它后面能被认出来、也能被清掉的唯一凭据。
2. **只在自己造的那一行上继续**：列表里**匹配那个前缀**的行，
   它上面的编辑 / 详情 / 复制 / 停用 / 删除都可以点。
   **别人的数据、系统预置的数据，一个按钮都不碰** —— 那部分仍然是无向的。

这条判据是**通用的**：它不认「团队」「适配器」「提示词模板」这些名词，
只认「这一行的文本里有没有我刚才那个前缀」。换个域、换个产品照样成立。

### 12.3 一条链要走完，断在哪一环要记下来

顺序是固定的，**每一环都记它发出去的请求**（这才是要拿去和 QA 脚本对账的东西）：

```
新建（POST）→ 列表里找到自己那一行（GET 列表）
  → 进详情（GET 详情 + 详情页里新解锁的子标签页，每一个都记）
  → 编辑（PUT/PATCH）→ 回列表确认改动生效（GET）
  → 删除自己那一条（DELETE）→ 确认真的没了（GET）
```

**断在哪一环，就记在哪一环** —— 这几种情形在报告上必须是不同的格子，
不能一起塌成「这个域没有新建功能」：

| 断点 | 含义 | 谁的问题 |
|---|---|---|
| 找不到表单 | 「新建」点了没反应 / 跳到一个空页 | 可能是产品 bug，也可能是我们没认出层 |
| 表单填不出来 | 有必填项猜不出（依赖另一条数据、要验证码、要上传文件） | 我们的，但**必须留痕**，不许静默跳过 |
| 提交失败 | 400/422 —— 填的值不合规 | 我们的（记下服务端的报错原文，那是最好的线索） |
| 建成功但找不到自己那一行 | 列表没刷新 / 分页在后面 / 需要审批才可见 | **这本身是一条发现** |
| 找不到编辑入口 | 这个对象确实不可编辑（也可能藏在详情页里） | 记成事实，不当缺口 |
| **删不掉** | 自己造的数据删不了 | **产品 bug，而且是最值钱的那种发现**；同时**必须报环境残留** |

### 12.4 三条硬约束（少一条就不许开跑）

1. **必须自带清理，而且清理要能查账。** 造了没删就是被测环境的垃圾，
   下一趟会看见自己上一趟造的数据 —— 那时候「列表里有 3 条」这类判断全部失真，
   而失真的方向是**看起来更正常**。清不掉的一律进残留清单（`residue.py` 那一路），
   不允许"跑完就算了"。
2. **只造、只改、只删自己前缀的那一条。** 判据在文本前缀上，不在按钮名字上；
   前缀匹配不上的行，退回无向规矩（一个写按钮都不点）。
3. **每一页最多一条链、一次新建。** 不是省时间，是**别把环境撑爆**：
   一页造一条、跑完删掉，环境净变化为 0；一页造十条，删漏一条就留一堆。

### 12.5 做完之后，报告里哪几格会变

这才是判断这一批值不值得做的地方：

- **P 边第一次会有写接口**。现在 668 条边全是 GET，做完会出现
  POST/PUT/DELETE —— 那 120 条 G2 里会有一部分转成「页面确实在用、
  他脚本没测」（G1），**那是第一次能拿写操作去质问覆盖率**。
- **页数会涨一截**，而且涨的是详情页和子标签页 —— 空列表进不去的那些。
- **表单字段从 27 涨到真实量级**。现在的 27 里绝大多数还是搜索框。
- **多一份「链条断点」清单**，逐页说清这个域的新建/编辑/删除到底走不走得通。

⚠ **不要把「填不出来的表单」做成跳过。** 这一批最容易假绿的地方就在这儿：
猜不出必填项就悄悄跳过，账本上和「这一页没有新建功能」一模一样，
而报告会显得很干净。**填不出来是一条明账，不是一个 0。**

## §13 需求补充（2026-09-04 下午，同一轮）：先**读懂这个域测的是什么**，才有资格判他写得对不对

**用户原话（两句连着说的）**：

> 「但是有一些业务逻辑怎么操作你要通过场景和脚本去发现，
> 不然你可能并不知道保存了要干嘛、链路是什么样的、怎么来审批之类的。」
>
> 「这就是根据测试场景和脚本进行探索测试，摸清楚这个域测的是个啥 ——
> **你懂了才能判断别人写的对不对、全不全。**」

### 13.0 这一节改的是**评审的立场**，不只是多点几个按钮

§11 和 §12 都还停在「页面上有什么、我能不能操作」。**判「他写得全不全」需要的
是另一样东西：这个域的业务本来该怎么走。** 不知道「保存完还要提交、提交完要换个
账号审批」，就只能对着端点清单数数 —— 数出来的「他少测了 120 条」里，
有多少是他真漏了、有多少是那条路根本走不到，一条都分不出来。

**顺序因此是固定的：先读懂链路 → 再照着链路去页面上走 → 走出来的流量才是判据。**

### 13.1 §12 那条链只是骨架，真实业务链比它长

§12 写的是 `建 → 详情 → 编辑 → 删`。**在有审批、有状态机的模块上这条走不完**：

- 保存出来的是**草稿**，还要「提交」；提交完是**待审**，还要**换一个账号**去「通过」；
  通过了才「生效」，生效之后才有「停用 / 撤销 / 新版本」那一层按钮。
- 盲点特别毒：我们建完一条草稿，页面**一点错都不报**，
  账本上「建成功」那一格是绿的 —— 而这条业务其实一步都没往前走。
- 还有一半在**另一个账号**手里。第 5 趟已经用 7 个角色各登了一次，
  但每个角色**各走各的**，没有「A 提交、B 审批」这种跨账号的接力。

### 13.2 链路骨架从哪儿来：**同一个脚本文件里的调用顺序**

这一条不需要问模型，也不需要按域写代码：

> **QA 那 153 条 shell 场景，每个脚本文件内部按顺序调的那几个端点，
> 就是一条业务链路的骨架。**

`POST /x` → `POST /x/{id}/submit` → `POST /x/{id}/approve` → `GET /x/{id}`
这个顺序是他写在文件里的**事实**，静态就能抽（Q 边解析器已经在抽调用点了，
现在多留一个「在这个文件里排第几」）。17 条 Playwright spec 同理。
场景清单里那句场景名（他自己写的中文标题）是同一件事的另一半线索。

拿到骨架之后，链路的每一环**对应页面上哪个按钮**是**现成的**：
批 1 / 批 2 已经建立了「点了 X → 发出 `POST /a/b`」这张对应表（P 边）。
两边一拼，就知道**该按什么顺序点哪几个按钮** —— 全程没有一个产品名词，
换域换产品照样成立。

### 13.3 ⚠ 和 §4 的边界：脚本只许**提出假设**，不许**下结论**

§4 否掉的是「拿 shell 调用倒推出一段他在页面上的操作步骤」，
理由是编出来的 UI 步骤**没有判据能验对错、编错了不报错**。这一条**继续有效**，
所以这里的用法必须卡死在一句话上：

> **脚本决定"去点什么、按什么顺序点"；结论只由"真点下去之后页面发出了什么"决定。**

具体三条：

1. 骨架**走通了**才算这条链存在 —— 记的是**真实发出的请求**，不是脚本里那几行。
2. 骨架**走不通**（页面上找不到「提交」这个按钮 / 点了没反应）
   → 记成一条**发现**，两种可能都写清：他脚本测的是页面做不到的事，
   或者页面改了他没跟上。**不许把脚本里那一步当成"页面也有"写进报告。**
3. 骨架里有、我们在页面上**一次都没触发过**的端点，仍然按 G2 记
   —— 别因为"脚本里写了"就当它被覆盖了。

### 13.4 「保存完还没走完」这件事怎么自己判出来

不靠猜，靠**跟同一张列表里别人那些行比**：

- 我们那一行的**状态列**是 `draft` / `pending`，而列表里既有的行是 `active`
  → **这条链还没走完**，继续在这一行上找下一个动作按钮。
- 我们那一行的状态和既有行**一样**了 → 这条链走到头了。
- 列表里根本没有状态列 → 这个对象没有状态机，`建 → 改 → 删` 就是全部。

这个判据也是通用的：它只比较「我这行的状态文本 vs 别人行的状态文本」，
**不认识** `draft`、`pending`、`active` 这些词具体什么意思。

### 13.5 跨账号那一环：**403 就是路标**

审批那一步，用建数据的那个账号点下去大概率是 **403**。
**403 不是失败，是信息**：它说明这一步该由别人做。做法：

1. 建数据的账号先把能做的做到底（建 → 提交），停在 `pending`。
2. 换我们已经登过的**其它角色**，去同一页找那条带我们前缀的数据，
   点「通过 / 驳回」。**谁点成了，就记下"这一步归这个角色"** ——
   这是一份对方清单里没有的东西（他的脚本拿 token 直接打接口，
   「页面上谁看得见这个按钮、谁点得动」他那边根本没有记录）。
3. 7 个角色都 403 / 都看不见这个按钮 → 记成断点，**不猜**。

⚠ **跨账号接力必须把清理也接过来。** 一条数据在 A 手里建、在 B 手里通过，
最后可能只有 B（或者只有管理员）删得掉。**清理要顺着链路的最后一个账号走**，
否则「跑完删干净」这句话在有审批的模块上一定不成立，
而残留会让下一趟的「列表里有几条」全部失真。

### 13.6 这一批要交的新东西：一份**业务链路清单**（按域）

每条链一行，逐环写清四样：

| 这一环 | 页面上点哪儿 | 谁能点 | 真走通了吗 |
|---|---|---|---|
| 建 | 「新建适配器」按钮 | 建数据那个角色 | ✅ `POST /adapters` |
| 提交 | 详情页「提交审批」 | 同上 | ✅ `POST /adapters/{id}/submit` |
| 审批 | 审批页「通过」 | **只有 platadmin 点得动**（其余 6 个角色 403 / 看不见） | ✅ `POST /approvals/{id}/approve` |
| 生效确认 | 回列表看状态列 | 任意 | ✅ 状态从 pending 变 active |
| 删除 | 列表行「删除」 | 待测 | ❌ 断点：403，7 个角色都删不掉 → **报残留** |

（上表是**格式示例**，不是实测结果 —— 域名、角色名、端点都要跑出来才算。）

**这份表是这一批真正的产出。** 它回答的是「这个域的业务到底怎么走、每一步谁能做」，
而对方的清单和脚本里都没有这一层（他打的是接口，绕过了"页面上谁看得见这个按钮"）。
拿它去和他的场景清单对账，才是「覆盖得全不全」这句话的完整答案。
